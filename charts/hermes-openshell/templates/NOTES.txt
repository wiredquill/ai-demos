Hermes is starting as OpenShell sandbox "{{ .Values.sandbox.name }}" from
  {{ include "hermes-openshell.sandboxImage" . }}
under the "{{ .Values.profile }}" profile (Hermes approvals: {{ get .Values.approvals .Values.profile }}).
{{- if eq .Values.profile "dangerous" }}

WARNING: the dangerous profile lets any program in the sandbox reach almost
any public website on ports 80/443, and Hermes runs commands without asking.
Demo use only.
{{- end }}

Watch the client create it:
  kubectl -n {{ .Release.Namespace }} logs -f deploy/{{ include "hermes-openshell.clientName" . }}

Browser terminal:
{{- if eq .Values.service.type "NodePort" }}
  kubectl -n {{ .Release.Namespace }} get svc {{ include "hermes-openshell.fullname" . }}   # http://<node>:<nodePort>
{{- else }}
  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "hermes-openshell.fullname" . }} 7681:{{ .Values.service.port }}
  # then http://localhost:7681
{{- end }}

A shell inside the sandbox (run `hermes` there):
  kubectl -n {{ .Release.Namespace }} exec -it deploy/{{ include "hermes-openshell.clientName" . }} -- openshell sandbox connect {{ .Values.sandbox.name }}

Swap the network rules live to another profile (filesystem and process rules
only change when the sandbox is recreated: change the profile in this form):
  kubectl -n {{ .Release.Namespace }} exec deploy/{{ include "hermes-openshell.clientName" . }} -- \
    openshell policy set {{ .Values.sandbox.name }} --policy /etc/hermes/profiles/lockdown.yaml --wait
